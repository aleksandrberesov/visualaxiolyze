# VisualAxiolyze — Руководство пользователя

VisualAxiolyze — визуальный инструмент для построения пайплайнов предобработки данных для GLM-моделирования. Загрузите датасет, опишите его схему, а затем итерационно добавляйте трансформеры на интерактивном канвасе — с возможностью ветвиться и сравнивать альтернативные подходы к генерации признаков.

---

## Быстрый старт

### 1. Загрузите датасет
**File → Load data (CSV / Parquet)…**  
Выберите CSV или Parquet файл. Приложение создаёт **корневую вершину** графа пайплайна.

### 2. Опишите схему данных
Автоматически открывается диалог схемы. Назначьте роли столбцам:

| Роль | Что означает |
|---|---|
| **Target** | Целевая переменная для моделирования (например, `loss_amount`) |
| **Exposure** | Весовой/офсетный столбец (например, `exposure_days`); если его нет — создайте синтетический |
| **Index** | Идентификатор строки — сквозной через все преобразования, не используется как признак |
| **Numeric / Categorical / Date** | Типы признаков — исправьте здесь ошибки автодетекции |

Нажмите **Save**. Корневая вершина на канвасе окрасится в зелёный.

---

## Построение пайплайна

### 3. Добавьте трансформер
1. Кликните по вершине на канвасе, чтобы выделить её (подсветится рамкой).
2. В **левой панели → Transformers** кликните нужную кнопку трансформера — на канвасе появится новый узел, связанный с выбранной вершиной.

### 4. Настройте трансформер
Откроется диалог конфигурации. Заполните параметры:
- **Выбор столбцов** — кликайте по бейджам столбцов (зелёный = выбран, серый = нет) или вводите имена вручную.
- Параметры со значением `null` заполняются из схемы данных автоматически при обучении.

Нажмите **Submit** для сохранения. Статус узла становится **setted** (зелёный).

### 5. Обучение и применение
| Кнопка | Действие |
|---|---|
| **Fit** | Обучает трансформер на данных родительской вершины; узел становится **fitted** (синий) |
| **Apply** | Запускает `transform()` — материализует дочернюю вершину; узел становится **transformed** (оранжевый) |

При ошибке во время обучения узел остаётся в статусе **setted**, сообщение об ошибке видно в тултипе узла.

### 6. Ветвление для экспериментов
Выделите **любую существующую вершину** (не обязательно листовую) и добавьте к ней ещё один трансформер. Это создаёт параллельную ветку — можно сравнивать несколько подходов к предобработке на одном канвасе.

## Анализ данных

Кликните по вершине, затем используйте **вкладки правой панели**:

| Вкладка | Содержимое |
|---|---|
| **Distribution** | Гистограмма / KDE для выбранного столбца и описательные статистики |
| **Correlation** | Матрица корреляций (MI, Chi², ANOVA) для выбранного набора столбцов |
| **Feature Importance** | Относительная важность признаков в данной вершине |
| **Grouped Stats** | Среднее/количество по целевой переменной в разрезе категориального признака |
| **Mixture Fit** | Подгонка смеси распределений для числового столбца |

---

## Доступные трансформеры

| Трансформер | Что делает |
|---|---|
| **Binning** | Дискретизирует числовые столбцы в бины (авто или заданное количество) |
| **Target Encoding** | Заменяет категориальные значения агрегированной статистикой по таргету |
| **Category Mapping** | Ручное перекодирование категорий (группировка / переименование уровней) |
| **Date** | Разбирает столбцы с датами → числовые столбцы год и месяц |
| **Date Difference** | Вычисляет разницы между парами столбцов с датами |
| **Cyclic** | Кодирует периодические признаки в пары sin/cos (например, месяц года) |
| **Mathematical** | Применяет log, sqrt, square, exp и др. к числовым столбцам |
| **Imputation** | Заполняет пропуски (медиана/мода или константа) |
| **Numeric → Categorical** | Преобразует числовые столбцы в упорядоченные/неупорядоченные категориальные |
| **Feature Pair** | Декартово произведение двух групп категориальных столбцов |
| **Column Remover** | Удаляет столбцы из датасета |
| **Transliterator** | Транслитерирует названия столбцов с кириллицы на латиницу |

## Сохранение и загрузка

### Экспорт проекта
**File → Export…** — выберите режим:

| Режим | Что сохраняется |
|---|---|
| `structure_only` | DAG пайплайна + схема + расположение узлов. **Без данных.** Для передачи коллегам; они подгружают свой датасет. |
| `full` | То же + активный датасет в виде CSV-текста. Удобно для небольших файлов (< ~50 МБ). |
| `full_parquet` | То же + датасет в виде компактного Parquet, закодированного в base64. |

Помимо экспорта, YAML автоматически сохраняется в `user_pipelines/<user>/` при каждом изменении.

### Импорт / продолжение работы
**File → Load saved graph (JSON / YAML)…** — выберите ранее экспортированный YAML. Пайплайн восстанавливается вместе с конфигурациями трансформеров и позициями узлов. При режиме `structure_only` сначала отдельно загрузите датасет.

## Цвета и статусы узлов

| Цвет | Статус | Значение |
|---|---|---|
| 🟢 Зелёный | `setted` | Конфигурация сохранена, трансформер ещё не обучен |
| 🔵 Синий | `fitted` | `fit()` выполнен успешно |
| 🟠 Оранжевый | `transformed` | Данные прошли через трансформер |
| 🟣 Фиолетовый | `completed` | Обучен и полностью вычислен |

## Советы

- **Переименовать проект**: кликните по имени проекта в верхней панели и введите новое.
- **Сохранить исходные столбцы**: у большинства трансформеров есть флаг `keep_original` — включите, чтобы сохранить исходный столбец рядом с новым.
- **Исправить схему после загрузки**: откройте панель схемы в любой момент через кнопку схемы в панели управления.
- **Ошибки не ломают граф**: если `fit()` завершился с ошибкой, она сохраняется на вершине, а узел остаётся на канвасе — исправьте конфигурацию и повторите попытку, не теряя остальные узлы.
