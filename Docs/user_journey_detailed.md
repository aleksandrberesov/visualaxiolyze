# Детальный пользовательский путь: Работа с графом экспериментов

## Обзор

Этот документ описывает детальный пользовательский путь для работы с графом экспериментов машинного обучения в системе анализа промышленных данных. Рассматриваются два основных сценария: создание нового графа с нуля и продолжение работы с существующим графом. После инициализации все дальнейшие операции (добавление трансформеров, обучение моделей, анализ результатов) выполняются одинаково независимо от способа начала работы. Документ фокусируется на бизнес-логике процесса, описывает текущие и целевые реализации ключевых этапов, а также ссылается на существующие классы и функции системы.

## 1. Инициализация работы с графом экспериментов

Пользователь начинает работу с графом экспериментов одним из двух способов:

### 1.1 Создание нового графа (с нуля)

**Пользователь загружает исходные данные** из CSV/Excel/feather файла или передает готовый DataFrame в систему и создает корневую вершину нового графа.

**Текущая реализация:**
- Пользователь работает напрямую с pandas DataFrame в Jupyter ноутбуке
- Система поддерживает известные типы numeric (int, float), categorical (str, object), datetime, ordered как разновидность категориальных
- Типы данных распознаются, пользователь может скорректировать автоматическое распознавание

**Целевая реализация:**
- Интеграция с распространенными источниками данных, прямое чтение с диска
- **Graph Engine** инициализирует новый граф эксперимента: система создает корневую вершину графа преобразований с исходными данными
- **Schema Tracker** создает первичную схему данных с метаинформацией о типах столбцов

### 1.2 Продолжение работы с существующим графом

**Пользователь загружает сохраненный граф** и выбирает вершину для продолжения экспериментов.

**Целевая реализация:**
- **Graph Loader** восстанавливает структуру графа из метаданных
- **Graph Canvas** визуализирует граф для выбора рабочей вершины
- **Node Selector** позволяет выбрать любую вершину как отправную точку

### 1.3 Выбор рабочей вершины

**После инициализации пользователь выбирает вершину** для дальнейших экспериментов (корневую для нового графа или любую существующую для продолжения).

### 2. Конфигурирование препроцессинга

**Основная абстракция системы - граф экспериментов**, где вершины представляют состояния данных (с актуальной схемой и доступной аналитикой), а ребра - обученные трансформеры между состояниями. Пользователь итерационно строит граф, добавляя к выбранным вершинам новые трансформеры, которые после обучения и тестового применения (`transform()`) создают дочерние вершины с преобразованными данными.

**Важное противоречие**: система должна обеспечивать доступность вершин для анализа, но при росте графа до десятков вершин полное кэширование данных становится ресурсозатратным, а полное пересчет от корня - медленным. Требуется балансированная стратегия кэширования.

#### 2.1 Конфигурирование трансформера

**Пользователь выбирает базовый трансформер** из библиотеки системы или копирует уже сконфигурированный.

**Два сценария конфигурирования:**
- **С нуля** - система показывает только доступные свойства на основе схемы родительской вершины
- **Предварительно сконфигурированный** - система проверяет совместимость и подсвечивает недоступные параметры

**Контекстная валидация параметров**: система анализирует пригодность операций (например, логарифмирование при отрицательных значениях, экспонента при больших значениях) на основе расширенной схемы данных.

**Пользователь определяет конфигурацию трансформера:**

1. **Списки столбцов:**
   - **Основные столбцы** (`features_to_transform`) - выбираются из схемы данных
   - **Вспомогательные столбцы** (`auxiliary_columns`) - веса, цели, референсные столбцы

2. **Параметры настройки** - задаются пользователем через интерфейс:
   - **Пользовательские решения**: пороги, количества бинов, стратегии обработки
   - **Схемные параметры**: форматы дат, типы агрегаций, методы группировки
   - **Расширенная схема данных**: частоты категорий, персентили для числовых признаков, вычисляемые при первичной обработке и дополняемые при появлении новых столбцов

**Текущая реализация:**
- Система предоставляет трансформеры среднего слоя: GLMDateTransformation, GLMTargetTransformation, GLMBinningTransformation, GLMCyclicTransformation и др.
- Конфигурация происходит в коде через параметры конструктора
- Отдельные интерфейсы: `binning_interface()`, `cyclic_feature_config_interface()`, `GLMModelSelector`
- Подсказки из данных не реализованы, пользователь задает параметры вручную

**Принципы разделения параметров трансформеров:**

Параметры трансформеров разделяются на три категории в зависимости от их природы и источника:

- **Пользовательские решения** - аналитические решения, требующие экспертного суждения: пороговые значения (n_bins, min_samples), методы обработки (methods, aggregations), доменные знания (periods для циклических признаков), первичный выбор столбцов (target_column в SmartDataFilter, first_group/second_group в FeaturePair, columns_to_remove), сложные конфигурации (mappings, transformations, differences), специальные случаи (date_format при нестандартных форматах)

- **Схемные параметры** - указания на структурные элементы данных и технические настройки: ссылки на уже определенные столбцы (features_to_transform когда столбцы заданы в конфигурации), правила именования (separator, new_index_name), технические флаги (keep_original, collision_strategy, unknown_strategy)

- **Расширенная схема данных** - характеристики, вычисляемые из содержимого данных: статистики распределений (частоты категорий, квантили, диапазоны значений), метаданные для валидации (типы категорий, статистики по целевой переменной)

**Примечание:** Выбор столбцов является контекстно-зависимым параметром - при первичном определении или новом аналитическом выборе это пользовательское решение, при ссылке на уже определенные в конфигурации столбцы - схемный параметр. Разделение выполнено по принципу преобладающей природы параметра в конкретном трансформере.

**Доступные трансформеры и их параметры:**

- **Transformer Palette** в UI предоставляет визуальный каталог доступных трансформеров
- **Configuration Panels** генерируют унифицированные интерфейсы на основе расширенной схемы данных
- Конфигурирование разделено во времени с обращением к данным - сначала вычисляется расширенная схема (вне конфигурирования), затем на ее основе происходит конфигурирование

#### 2.2 Обучение и тестовое применение трансформера

**Пользователь инициирует обучение и тестовое применение трансформера** (`fit()` и `transform()`), что приводит к материализации новой вершины графа с преобразованными данными и обновленной схемой.

**Текущая реализация:**
- Трансформеры следуют sklearn интерфейсу: `fit()`, `transform()`, `fit_transform()`
- Поддержка интеграции в sklearn Pipeline
- Каждый трансформер может сохранять исходные признаки (`keep_original` параметр)

**Целевая реализация:**
- **Graph Engine** создает новую вершину с обученным трансформером как ребром
- Система обеспечивает атомарность операции: либо трансформер успешно обучен и вершина создана, либо состояние графа не изменяется
- При создании новых столбцов автоматически вычисляется их расширенная схема

#### 2.3 Итерационное построение пайплайна

**Пользователь продолжает добавлять трансформеры** к выбранным вершинам, постепенно создавая сложные пайплайны предобработки.

**Текущая реализация:**
- sklearn Pipeline поддерживает последовательное применение трансформеров
- Система сохраняет всю цепочку трансформаций для воспроизводимости

**Целевая реализация:**
- Каждый новый трансформер добавляется как новое ребро и вершина в графе
- Система отслеживает эволюцию схемы данных через все трансформации
- Компоненты системы обеспечивают оптимальное управление памятью и кэширование
- Система валидирует совместимость каждого нового трансформера с схемой данных родительской вершины

#### 2.4 Ветвление для экспериментов

**Пользователь создает альтернативные ветви обработки** для сравнения различных подходов к трансформации данных. Система позволяет начинать новые эксперименты с любой промежуточной вершины графа.

**Текущая реализация:**
- Нет поддержки ветвления, пользователь работает с линейными пайплайнами
- Промежуточные состояния не сохраняются - при неудачном эксперименте приходится воссоздавать весь путь от загрузки данных

**Целевая реализация:**
- **Graph Engine** поддерживает создание множественных дочерних вершин от одного родителя
- Пользователь может копировать и адаптировать конфигурации трансформеров между ветвями
- **Graph Canvas** визуализирует древовидную структуру экспериментов
- Система позволяет параллельное выполнение независимых ветвей обработки

### 3. Анализ промежуточных результатов

#### 3.1 Валидация и профилирование данных

**Пользователь просматривает автоматически сгенерированный анализ состояния данных в вершине**, включающий статистики по столбцам, распределения значений, выявленные проблемы качества данных.

**Текущая реализация:**
- Ручное исследование данных через pandas методы в отдельном ноутбуке, передача актуального состояния датафрейма через сохранение и чтение с диска
- Функции в `visualization.py` для создания графиков и отчетов
- Нет автоматизированного профилирования

**Целевая реализация:**
- **Node Analytics Engine** автоматически анализирует состояние данных в вершине
- **Sample Generator** создает представительные выборки для быстрого анализа больших датасетов
- Система предупреждает о потенциальных проблемах: пропущенные значения, выбросы, несбалансированность, пригодность для линейных предикторов (VIF, мультиколлинеарность)

#### 3.2 Создание аналитических отчетов

**Пользователь создает детальные отчеты для анализа данных в выбранной вершине** для принятия решения о следующих шагах преобразования.

**Доступные типы аналитических материалов:**
- **Профиль данных (отчет)** - автоматическая генерация статистик и метаданных
- **Отчетный документ** - комплексный анализ с графиками и интерпретацией
- **Распределения величин** - детальный анализ распределений по столбцам
- **Корреляционные матрицы** - анализ взаимосвязей между переменными
- **Псевдокорреляционные матрицы** - анализ нелинейных зависимостей
- **Интерактивные комментарии** - пояснения к математическим артефактам с подсказками по трансформациям

**Текущая реализация:**
- Ручной анализ через pandas методы и визуализации
- Функции в `visualization.py` для создания графиков и отчетов
- Создание профиля требует доступ в интернет (не подходит для работы с чувствительными данными)

**Целевая реализация:**
- **Node Analytics Engine** автоматически обновляет аналитику новой вершины
- **Report Generator** создает различные типы отчетов по запросу
- **Insight Engine** генерирует контекстные подсказки и рекомендации по трансформациям
- Система предлагает анализ подгрупп столбцов для выявления скрытых паттернов

### 4. Создание и обучение моделей

#### 4.1 Выбор листовой вершины для моделирования

**Пользователь выбирает одну или несколько вершин графа** в качестве финальных точек для обучения моделей.

**Текущая реализация:**
- Финальный DataFrame (к которому применяется транслитератор) является исходным для моделирования
- Нет явной концепции вершин

**Целевая реализация:**
- **Graph Engine** идентифицирует листовые вершины как кандидатов для моделирования (листьев-моделей)
- Пользователь может назначить несколько вершин как листья для сравнения моделей на разных этапах обработки
- Система поддерживает до 20 листьев-моделей в одном графе согласно техническим требованиям
- В одной родительской вершине можно разместить несколько листьев-моделей

#### 4.2 Конфигурирование параметров модели

**Пользователь настраивает параметры GLM модели**, включая выбор семейства распределения, функции связи, стратегии обработки exposure и весов, параметры регуляризации, стратегии валидации.

**Текущая реализация:**
- Функция `fit_glm_model()` в `glm_analysis.py` принимает параметры: `family`, `link`, `exposure_column`, `weight_column`, `exposure_strategy`
- Система поддерживает автоматический выбор стратегии через `EXPOSURE_WEIGHT_STRATEGIES`
- Функция `list_available_strategies()` предоставляет доступные опции

**Целевая реализация:**
- **Model Configuration Panel** адаптируется под схему данных выбранной вершины
- Система предлагает рекомендации (например, семейство распределения, байесовский vs обычный GLM), но решение остается за пользователем
- Пользователь может сохранять и переиспользовать конфигурации моделей
- **Открытый вопрос**: как согласовать стратегии валидации (train/test split, cross-validation, байесовский вывод) с препроцессингом, поскольку некоторые трансформеры (например, target encoding) должны обучаться только на train части. Предварительное решение: конфигурировать на всех данных, а переподготавливать с учетом стратегий при обучении моделей

#### 4.3 Обучение и валидация модели

**Пользователь инициирует обучение GLM модели (или набора моделей)** на данных выбранной листовой вершины. При наличии подбора гиперпараметров система проводит эксперименты на многообразии параметров.

**Текущая реализация:**
- Функция `fit_glm_model()` выполняет полный цикл обучения и возвращает `result_dict` с результатами (вектор аналитик)
- Система автоматически вычисляет метрики качества через `likelihood_utils.py`
- Стратегия train/test split вшита в код, не выделена как отдельная стратегия
- Поддержка различных семейств распределений: Gamma, Gaussian, Poisson

**Целевая реализация:**
- **Model Training Engine** координирует обучение множества моделей с различными параметрами
- **Hyperparameter Experiment Engine** проводит эксперименты по перебору/подбору параметров регуляризации
- **Model Analytics Engine** генерирует аналитику для каждой модели, создавая многомерную структуру результатов
- **Regularization Visualization Engine** создает графики зависимости метрик от параметров
- **Model Decision Engine** обеспечивает инструменты для выбора оптимальной модели

### 5. Анализ и сравнение моделей

#### 5.1 Исследование результатов модели

**Пользователь анализирует качество и интерпретируемость обученной модели** через автоматически сгенерированные отчеты и визуализации.

**Текущая реализация:**
- Функция `analyze_glm_model()` в `glm_analysis.py` создает детальный анализ результатов
- Функция `display_metrics()` предоставляет интерактивную таблицу с метриками качества
- Система генерирует читаемые формулы модели и доверительные интервалы коэффициентов
- Функция `export_model_results()` создает Excel и HTML отчеты

**Целевая реализация:**
- **Model Analytics Engine** автоматически обновляет анализ при изменении модели
- **Analytics Dashboard** предоставляет интерактивные дашборды с метриками и визуализациями
- Система генерирует объяснения важности признаков и влияния трансформаций
- **Export Engine** поддерживает множественные форматы экспорта результатов

#### 5.2 Сравнение альтернативных моделей

**Пользователь сравнивает качество моделей**, обученных на разных ветвях графа или с различными конфигурациями.

**Текущая реализация:**
- Функция `display_metrics()` поддерживает сравнение с предыдущими результатами через параметр `old_analysis_results`
- Ручное сравнение через анализ метрик в ноутбуке

**Целевая реализация:**
- **Model Comparison Engine** автоматически сопоставляет метрики множественных моделей
- **Visualization Engine** создает сравнительные графики и таблицы
- Система ранжирует модели по выбранным критериям качества
- Пользователь может создавать кастомные сравнительные дашборды

### 6. Экспорт и продуктивизация

#### 6.1 Изоляция оптимального пути

**Пользователь выбирает лучшую модель и изолирует путь от корневой вершины** до этой модели для продуктивного использования.

**Текущая реализация:**
- Нет поддержки разных путей (ветвления) в графе
- Pipeline сохраняется и не требует воссоздания для продакшена
- Приходится пересоздавать весь путь для построения альтернативных экспериментов

**Целевая реализация:**
- Система автоматически извлекает последовательность трансформеров от корня до выбранной модели
- Создает sklearn-совместимый пайплайн из изолированного пути
- Исключает неиспользуемые ветви и оптимизирует производительность пайплайна

#### 6.2 Экспорт артефактов модели

**Пользователь экспортирует обученную модель и пайплайн** в формате, готовом для развертывания в продуктивной среде.

**Текущая реализация:**
- Функции `savem()` и `loadm()` в `model_io.py` сохраняют и загружают модели с метаданными
- Поддержка сохранения пайплайнов предобработки, name_mapping, и конфигураций фильтрации
- Автоматическое хеширование для уникальной идентификации моделей

**Целевая реализация:**
- Система предоставляет пошаговый интерфейс для экспорта моделей
- Упаковывает модель, пайплайн, метаданные и документацию в единый артефакт
- Поддерживает семантическое версионирование экспортированных моделей
- Генерирует конфигурации для различных платформ развертывания (Docker, Kubernetes, cloud services)
- Обеспечивает валидацию целостности экспортированных артефактов

#### 6.3 Валидация экспортированной модели

**Пользователь тестирует экспортированную модель** на новых данных для подтверждения корректности экспорта.

**Текущая реализация:**
- Ручная валидация через применение загруженной модели к тестовым данным
- Нет автоматизированных тестов целостности экспорта

**Целевая реализация:**
- Система автоматически выполняет тесты целостности экспортированного артефакта
- Сравнивает предсказания оригинальной и экспортированной моделей на контрольной выборке
- Генерирует отчет о готовности модели к продуктивному использованию

## Ключевые сущности системы

### Текущие реализованные компоненты

- **GLMTransformation** - базовый класс для всех трансформеров
- **GLMModelSelector** - виджет для конфигурирования модели
- **fit_glm_model()** - основная функция обучения GLM
- **analyze_glm_model()** - функция анализа результатов
- **savem()/loadm()** - функции сохранения/загрузки моделей
- **display_metrics()** - интерактивное отображение метрик

### Целевые архитектурные компоненты

- **Graph Engine** - управление структурой графа экспериментов
- **Hyperparameter Experiment Engine** - эксперименты по подбору параметров
- **Model Training Engine** - координация обучения множества моделей
- **Model Analytics Engine** - аналитика результатов моделей
- **Model Decision Engine** - инструменты выбора оптимальной модели
- **Report Generator** - создание аналитических отчетов
- **Insight Engine** - генерация контекстных подсказок
- Отслеживание схем данных
- Управление памятью и кэширование
- Инструменты экспорта и валидации моделей

## Технические ограничения и требования

- Поддержка датафреймов до 10^8 строк и 150 столбцов
- До 20 листьев-моделей в одном графе
- Ленивая материализация с эффективным кэшированием
- Полная сериализуемость состояния для воспроизводимости
- Инкрементальные обновления при изменении графа
