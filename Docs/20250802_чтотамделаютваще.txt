Пользователь хочет построить модель, которой будет "понятно" как объяснить зависимость, имеющуюся в данных. Модель хороша, если подходит к данным.
Для этого пользователь строит много вариантов преобразования данных и моделей, рассматривает получающиеся результаты.
Граф преобразований: (дерево состояний с модельными листьями)
* корень - данные (датафрейм; становится корнем когда дополняется схемой - называем обязательные элементы из числа столбцов)
* вершины - данные (схема и датафрейм) - получаются применением трансформера (.transform() )
* ребра - трансформеры (бывают запланированные, обученные - после выполнения .fit() )
* листья - обученные модели (после выполнения их .fit() )
* ребра к этим листьям - конфигурации моделей

Пользователь хочет выбрать наилучшую обученную модель, и тогда путь к модели + сама модель будут зафиксированы и переданы на прод.

Ребра можно добавлять к произвольной вершине, конфигурировать (если еще нет вершины за ним) и рассматривать конфигурацию. То, какую конфигурацию выбрать (и даже предложить), зависит от данных: всегда от схемы данных, и для некоторых - от датафрейма (значений).
Вершины и листья можно рассматривать и сохранять аналитику (pdf, xlsx)

этот пользователь строит того графа. для этого у него есть канвас, куда он кидает очередное ребро, и получается еще одна вершина. ребро он выбирает графически - одного из (10) трансформеров или одну из (1) моделей

# Вершина
данные + схема данных. Данные могут весить от "много" до "с трудом загрузили", это табличка ~ 10^2 * 10^(6...8)Схема данных это словарь из около 5 значений, некоторые из них- списки длиной не больше ширины таблички.

## Для любой вершины можно:
* посмотреть на данные (взять n=5 первых строк датафрейма)
* создать стандартный ProfileReport
* изучить распределения (выбрать одну / несколько фичей - для каждого из методов свои правила - посмотреть в картинки)
** почитать про математику за подбором распределений
* изучить корреляции (для выбранного подмножества - посмотреть и сохранить картинки)
** почитать про математику за этими методами корреляций
* сохранить данные

# Ребро
это трансформер - правило для преобразования данных. У трансформера есть конфигурация (что он с какими столбцами должен сделать). Затем трансформер обучается (фит) и становится готов к применению.

## Для любого ребра можно:
* его добавить - выбрать из заготовок без конфигурации или скопировать другое ребро
* выделить для копирования
* посмотреть конфигурацию
* исправить конфигурацию (подсвечиваются несоответствия - какие столбцы упомянуты, но в вершине их нет) если еще не обучен
* сконфигурировать - выбрать из списков / табличек свойства. Эти свойства всегда зависят от схемы данных и иногда от самих данных (придется обратиться к данным?)
* обучить (это однозначно обращение к данным) - это произведет заодно и вершину после него, т.е. новое состояние схемы данных и датафрейма
* посмотреть, обучен ли 

# Ребро модельное
это необученная модель, или другими словами конфигурация модели. К ней со стороны графа прилеплены последние преобразования данных (которые нужно выполнять один раз непосредственно перед запуском модели)

## что можно делать с модельным ребром:
* создавать его - выбирать из заготовок без конфигурации или скопировать существующее
* выделить для копирования
* конфигурировать - выбирать или менять семейство, функцию связи, диапазон для регуляризации и т.п., привязывать к схеме данных
** почитать про математику за каждым из параметров
* проверить обучена ли
* обучить
